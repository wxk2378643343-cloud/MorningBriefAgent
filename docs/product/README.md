## 维护规则

- **原地迭代**：需求细化、改数字、补边界，都改 `prd.md` 本体，不新建 `prd-v2.4.md`。
- **每次实质修改**：正文 + 版本记录表同步更新。
- **方向推翻才另起文档**：旧文档移入 `archive/`，并在上表登记作废原因。
- **不做清单不进文档**：边界用正面约束表达（"数据一律用通用格式存放"），不列"我们不做什么"。

## 归档约定

当一个文档被取代时：

1. 移动到 `docs/product/archive/`；
2. 文件名前加日期前缀，如 `2026-11-05-p0-prd.md`；
3. 在本文档的"已经作废的"表中加一行，写清作废原因。
